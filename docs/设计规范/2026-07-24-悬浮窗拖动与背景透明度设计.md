# 悬浮窗拖动与背景透明度设计

## 目标

Codex Beacon 不再固定遮挡屏幕顶部菜单栏。用户可以拖动悬浮窗，并直接调节主背景透明度；两项设置均在重启后保留。

## 交互设计

### 拖动

- 收起状态显示一个明确的拖动把手；从把手按下并拖动时移动整个原生窗口。
- 展开状态可从标题栏的非按钮区域拖动。
- 展开、设置、收起和隐藏按钮继续保持原有点击行为，拖动区域不覆盖这些控件。
- 用户首次运行或尚未拖动过时，窗口仍位于主屏幕顶部居中。
- 拖动结束后立即保存窗口的物理屏幕坐标。
- 启动时仅恢复仍落在当前任一显示器可见区域内的位置；显示器布局改变导致旧位置不可见时，使用默认位置。

### 背景透明度

- 设置页增加“背景透明度”原生滑杆，范围为 50%–100%。
- 滑杆调整的是背景可见程度：50% 最透明，100% 最不透明。50% 是保证浅色和复杂桌面背景下仍可读的安全下限。
- 默认值为 98%，与当前视觉效果基本一致。
- 调整即时生效并立即保存在本机。
- 透明度只影响悬浮窗主背景，不降低文字、图标、状态灯和控件本身的清晰度。
- 禁止在悬浮窗父容器上使用整体 `opacity`；文字、图标、状态灯、边框和交互控件始终保持原有不透明度。

## 实现范围

- 复用 `@tauri-apps/api` 已提供的窗口拖动、位置监听、坐标设置和显示器查询能力。
- 使用浏览器 `localStorage` 保存位置与透明度，不增加依赖或 Rust 配置文件。
- 使用 CSS 自定义属性驱动现有 `--surface` 背景透明度。
- 若持久化数据缺失、格式错误或坐标不可见，忽略该数据并安全回退到默认值。

## 验收标准

1. 收起和展开状态均能通过明确区域拖动窗口。
2. 拖动不会误触发展开、设置、收起或隐藏。
3. 关闭并重新启动后，窗口恢复到上次有效位置。
4. 旧坐标不在任何当前显示器内时，窗口回到顶部居中。
5. 设置页可在 50%–100% 间连续调节背景透明度。
6. 透明度调整即时生效，重启后保持。
7. 文字、图标和交互控件不随背景透明度一起变淡。
8. 在 50% 最透明档位下，浅色、深色和复杂桌面背景上均不存在文字不可见、状态难辨或控件边界消失。

## 验证

- 为持久化数据解析、透明度边界和可见区域判断留下最小自动化测试。
- 运行前端构建与 Rust 全量测试。
- 启动桌面应用，手动验证拖动、按钮点击、透明度即时反馈及重启恢复。
- 在浅色窗口、深色窗口和复杂图像上分别检查 50% 最透明档位，确认所有文字、状态和控件仍清晰可辨。
